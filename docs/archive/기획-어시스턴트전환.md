# 인사야 재구조화 기획 — 포털 → 어시스턴트 전환

> 문제의식: 콘텐츠(가이드 33·계산기 27·서식 24)는 많아졌지만 **기능이 얕고(조각들이 사일로), 메뉴가 과부하**라 "정리 안 된 느낌". 넓이만 늘고 깊이(차별점=AI 상담 흐름)는 안 깊어짐.
>
> 방향: **"상황 하나 → 끝까지."** 계산기·가이드·문서는 *메뉴*가 아니라 *AI가 쥐는 도구*. 넓이는 뒤(라이브러리·SEO), 깊이는 앞(연결된 여정)으로.

---

## 핵심 원칙
1. **어시스턴트 우선** — 홈 = AI 상담. 나머지는 접근 가능하되 전면에 나열하지 않음(점진적 노출).
2. **여정 > 도구 개수** — 깊이는 "27개 계산기"가 아니라 "한 상황이 진단→계산→문서→요약서로 매끄럽게 이어지는 경험".
3. **사일로 연결** — AI·계산기·문서·가이드가 서로를 호출·프리필·반영.
4. **라이브러리는 유지, 전시는 절제** — 33·27·24는 SEO·롱테일 자산으로 남기되 메가메뉴에 다 뿌리지 않음.

---

## Phase 1 — 메뉴 슬림화 (즉효, "정리 안 됨" 직접 해결)
- **상단 nav 재편**: `[근로자 megas][사업주 megas][도구▾]` → `[상황별 해결][계산기][가이드▾(근로자|사업주 통합)][문서센터][노무사]` + `[무료 AI 상담]` CTA. 로고→홈(AI).
  - 근로자·사업주 megas 2개 → **가이드 1개**(2열)로 통합
  - "상황별 해결"(solve)을 **최상위로 승격**(어시스턴트 척추)
- **계산기 페이지 스마트 진입**: 27개 평면 → "무엇을 계산할까요?" 검색 + **핵심 6개 우선** + 나머지 그룹 접기/펼치기
- **서브내비 절제**: 카테고리는 유지하되 시각 무게 축소

## Phase 2 — solve를 척추로 (깊이의 뼈대)
- SOLVE 시나리오 6 → **12~14개**로 확장(임금체불·부당해고·퇴직금·주휴·괴롭힘·성희롱·산재·실업급여·비정규직 차별·정리해고·대지급금 + 사업주 시나리오)
- 각 solve = **가이드→계산기(딥링크)→문서(팩)→노무사** 4단계 연결(이미 구조 존재, 확장·정비)

## Phase 3 — 기능 연결 (사일로 → 깊이의 실체)
- **AI 상담 → 계산기 인라인·프리필**: 대화에서 파악한 값(월급·근속 등)으로 관련 계산기를 대화 내에 임베드
- **계산기 결과 → 문서 자동채움**: 계산한 숫자가 진정서·내용증명에 반영 + 상담요약서에 추가
- **가이드 → 도구 3종 연결**: 각 글에 계산기·문서·"이걸로 AI 시작" 버튼(embed는 이미 존재, 표준화)

## Phase 4 — 홈(어시스턴트 입구) 강화
- 홈 AI 프롬프트에 **원탭 상황 칩**(임금체불·부당해고·퇴직금…) — 무엇을 물어야 할지 모르는 사용자 진입 마찰 제거

---

## 실행 순서
1. **Phase 1** (메뉴 통합·슬림화) ← 지금
2. **Phase 3-부분** (계산기↔문서 연결 = 깊이 증명)
3. **Phase 2** (solve 확장)
4. **Phase 4** (홈 칩)

## 유지/데모트 원칙
- 27 계산기·33 가이드·24 서식·SEO 정적페이지 = **유지**(자산). 단 "전시(메뉴)"는 절제.
- 사업주 전용 도구(자율점검·상시근로자수·인건비·사용촉진)는 근로자 흐름과 분리.
