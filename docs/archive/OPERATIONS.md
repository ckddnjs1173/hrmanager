# 노무사 연계 · 운영 모델 기획서 (제품 수준)

> 결정 사항: ① 상담 접수를 **운영자가 받아 노무사에게 전달**하는 모델로 갈지 ② 전달을 **어떤 방식**으로 할지 ③ 법적·개인정보 안전장치 ④ 과금 ⑤ 필요한 화면(노무사/운영자 대시보드).

---

## 0. 가장 중요한 전제 — 법적 안전선 (공인노무사법)
- 공인노무사법은 **사건 수임의 알선·소개(브로커링)를 제한**합니다.
- 위험: 운영자가 "이 사건은 이 노무사" 식으로 **건별로 배정하고 그 대가(건당비·성공보수)를 받으면** → 알선으로 해석될 수 있음.
- **안전한 구조**:
  - 운영자는 **"상담 준비된 고객 정보를 전달하는 정보·플랫폼 서비스"**를 제공.
  - 노무사는 **월 입점료/구독료/노출 광고비**를 냄(✅). **건당 수수료·수임료 쉐어 금지(❌)**.
  - 전달은 사용자(근로자) **동의 후**, 회사명·실명 **마스킹**된 요약서로.
  - 표현은 "추천/배정"❌ → "정보 전달/연결 요청"⭕.
> 즉 "운영자가 받아 전달"은 가능하되, **돈을 사건 결과에 연동하지 않는다**가 핵심.

---

## 1. 연계 모델 — 3가지 비교
| 모델 | 방식 | 장점 | 단점/리스크 |
|---|---|---|---|
| A. 직접 연결(현재) | 사용자가 노무사 선택 → 그 노무사에게 바로 접수 | 운영 부담 0, 알선 리스크 낮음 | 운영자가 품질·전환 관리 못함, 데이터 안 쌓임 |
| **B. 운영자 경유(추천)** | 접수 → **운영자 검수** → 노무사에게 전달 | 품질관리·요약서 정제·매칭·데이터 축적, 신뢰↑ | 운영 손이 감, 알선 표현/과금 주의 |
| C. 자동 매칭 | 지역·분야로 시스템이 자동 배정 | 확장성 | 알선 해석 리스크 가장 큼, 초기 과함 |

**추천: B (운영자 경유)** — 무자본 초기엔 운영자가 직접 검수·전달하며 품질과 신뢰를 만들고, 데이터가 쌓이면 일부 자동화. 단 과금은 입점/구독.

---

## 2. 데이터 흐름 & 상태(Status)
```
사용자: 노무사 상담 신청(요약서 동봉 동의)
   ↓  POST /api/booking  → 운영자에게 접수
[접수됨] → 운영자 검수(요약서 정제·마스킹 확인) → [검토완료]
   ↓ 노무사에게 전달(아래 §3 방식)
[전달됨] → 노무사 수락/연락 → [상담진행] → [완료] / [취소]
```
- 각 예약 레코드 상태: `received → reviewed → sent → in_progress → done / canceled`
- 운영자 대시보드에서 상태 전환·메모·전달 이력 관리.

---

## 3. 전달 방식 (핵심 질문) — 옵션 & 추천
| 방식 | 설명 | 비용/난이도 | 추천 |
|---|---|---|---|
| **노무사 대시보드** | 노무사가 로그인 → 배정된 상담·요약서 확인 | 개발 필요, 운영 깔끔 | ⭐ 장기 핵심 |
| **카카오 알림톡** | 노무사 휴대폰으로 "새 상담 도착" 발송(국내 표준) | 카카오 채널+템플릿 승인, 건당 9~15원 | ⭐ 자동 알림 |
| 이메일 | 요약서 PDF/보안링크를 노무사 메일로 발송 | 가장 쉬움(SMTP/API) | MVP 기본 |
| SMS/LMS | 문자 발송(알리고·NHN 등) | 저렴·간단 | 알림 보조 |
| 보안 공유 링크 | 만료되는 링크로 요약서 열람(아무 채널로 전달) | 간단, 유연 | 공통 기반 |

**추천 단계(무자본 → 확장)**
1. **MVP**: 접수 → **운영자 대시보드**에서 확인 → **보안 링크 생성** → 노무사에게 **이메일/카톡 수동 전달**. (자동화 전, 손으로 신뢰 구축)
2. **자동 알림**: 노무사에게 **카카오 알림톡**(또는 SMS)으로 "새 상담 + 열람 링크" 자동 발송.
3. **노무사 대시보드**: 노무사가 직접 로그인해 배정 상담을 확인·수락·메모(CRM). 알림톡은 "도착했어요" 트리거로만.

> 링크 기반이 핵심: 요약서는 **만료·접근제한 링크**로 열람 → 어떤 채널(메일/카톡/문자)로도 안전하게 전달.

## 4. 동의 · 개인정보 (필수)
- 신청 시 **명시 동의**: "상담 내용을 노무사에게 전달하는 데 동의합니다"(체크).
- 전달 정보: **마스킹된 요약서**(회사명·실명 ***) + 연락처(상담 목적, 노무사에게만).
- 보관·삭제: 보관기간 명시, 사용자 **삭제 요청** 처리. 노무사 미수락 건은 일정 후 파기.
- 링크: 만료(예: 7일)·1회성·노무사 식별 토큰.
- 로그: 누가 언제 열람했는지 기록(분쟁 대비).

---

## 5. 매칭 로직 (운영자 경유)
- 우선순위: ① **직접등록·입점 노무사** ② 지역(시/도·구) ③ 분야 일치 ④ 가용(오늘 상담가능).
- 초기에는 운영자가 수동 선택(품질). "추천"이 아니라 사용자가 고른 노무사 우선 + 미지정 시 운영자가 분야·지역으로 연결 요청.
- 자동 분배(라운드로빈)는 데이터·입점사 많아진 뒤. 그래도 과금은 입점/구독.

---

## 6. 과금 모델 (재확인 — 알선 회피)
- ✅ 노무사: **월 입점료 / 구독(프로필·상위노출) / 지역·분야 광고 / 예약관리 SaaS**.
- ❌ 건당 수수료 · 수임료 %.
- 사용자(근로자): 무료.
- 이렇게 하면 "돈이 사건 결과와 무관" → 정보·광고 플랫폼으로 안전.

---

## 7. 필요한 화면 (구현 대상)
### (a) 운영자(관리자) 대시보드 — `/admin`
- 접수 목록(상태·지역·분야·요약 미리보기), 상태 전환, 노무사 선택·전달, 전달 이력, 메모, 통계(접수·전환), 옵트아웃/삭제.
- 인증: 간단 비밀번호/토큰(환경변수).
### (b) 노무사 대시보드 (2차)
- 배정 상담 목록·요약서 열람·수락/메모. 로그인(노무사 계정).
### (c) 사용자 측
- 신청 모달에 **전달 동의 체크** 추가, 신청 후 "접수됐어요(요약서가 안전 링크로 전달됩니다)" 안내, 진행 상태 확인(선택).

---

## 8. 구현 단계 (제안)
1. **신청 데이터 보강**: `/api/booking`에 동의·요약서·상태 필드 추가, 보안 링크 토큰 발급.
2. **운영자 대시보드** `/admin`: 접수 확인 → 상태 관리 → 보안 링크 복사 → (수동) 전달.
3. **요약서 열람 페이지** `/r/:token`: 마스킹 요약서 + 만료·접근로그.
4. **자동 알림**(카톡 알림톡 or 이메일/SMS) 연동.
5. **노무사 대시보드**(로그인) — 입점사 늘면.

---

## 9. 사이트 전체를 "제품 수준"으로 — 진행 방식 제안
제가 PM처럼 기획을 끌고 가겠습니다. 산출물은 이미 다음으로 정리돼 있고, 항목별로 "현재→목표→구현"을 합의하며 진행합니다:
- `PRODUCT.md`(전체 페이지 제품화), `UPGRADE.md`(MVP→제품), `CONTENT.md`(콘텐츠·비주얼), `design/01~09`(디자인 시스템), **본 문서(운영·연계)**.
- 다음 디테일 후보: **결제·구독(노무사 과금)**, **회원/계정·이력**, **알림(카톡/메일)**, **관리자 운영툴**, **분석·전환 추적**, **배포·도메인·보안**.

> 권장 순서: 본 문서 §8(연계 운영 코어) → 관리자 대시보드 → 알림 → 결제. 각 단계마다 화면·데이터·플로우를 디테일 기획 후 구현.
