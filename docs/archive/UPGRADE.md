# 제품화 업그레이드 기획서 (MVP → Product)

> 범위: **프론트엔드·백엔드 전 영역**을 제품 수준으로. 제외 = (a) 사용자가 직접 준비할 외부 에셋(폰트·사진·영상), (b) 실제 AI API 연결(키 입력 단계). 단, AI의 프롬프트·스키마·플로우 "설계"는 제품 수준으로 준비.
> 핵심 철학: **정확성(법령·수치) · 신뢰(전문성·감수) · 완결성(상태·접근성·운영)**. "근사치/샘플/기본형"을 전부 "정식/실데이터/검증"으로 교체.

기준 사실(2026):
- 최저임금 **시급 10,320원**, 월 환산(209h) **2,156,880원**, 일급 **82,560원**. (출처: 고용노동부/최저임금위)
- 고용노동부 **표준근로계약서 7종**(정규직/기간제/단시간/연소/건설일용/외국인/외국인농축산) 및 임금명세서·표준취업규칙 공개 양식 기준.

우선순위: **P0**(제품 신뢰 직결·즉시) · **P1**(차별화·핵심) · **P2**(고도화).

---

## A. 문서센터 — "기본 초안" → "고용노동부 표준 양식 기반 정식 문서" 〔P0〕
현재: 자체 약식 6종, 텍스트 치환.
목표: **공식·전문가 수준 양식**으로 교체 + 정밀 입력/검증/출력.

- **표준근로계약서 7종 전면 채택**: 고용노동부 표준양식의 **필수 기재사항·문구·조항 구조** 반영(정규직/기간제/단시간/연소/건설일용/외국인 등). 단시간=근로일별 근로시간표, 연소=친권자 동의·연령증명, 외국인=영문 병기 등 유형별 차이 반영.
- **문서 종류 확장**: 임금명세서(법정 기재항목), 해고예고 통지서, 해고사유·시기 서면통지서, 권고사직 합의서, 경위서/시말서, 징계(경고/견책) 통지, 내용증명(임금·퇴직금 청구) 정식 양식, 노동청 진정서, (사업주)표준취업규칙 발췌·연차사용촉진 통지 등.
- **입력 UX**: 유형 선택 → 단계형 폼(필수/선택 구분, 검증: 날짜·금액·필수기재 누락 경고), 실시간 미리보기.
- **법정 필수기재 체크**: 근기법 제17조 항목 누락 시 경고(임금 구성·계산·지급방법, 소정근로시간, 휴일, 연차 등).
- **출력**: 인쇄 최적화 CSS(A4, 서명란·날짜·직인 영역), PDF 저장, .docx(후순위), 파일명 규칙.
- **고지/면책 + 출처 표기**(“고용노동부 표준양식 기반”), 자동 마스킹 옵션.
- 백엔드: `lib/docs.js`를 양식별 모듈로 분리 + 버전/출처 메타.

## B. 계산기 — "근사치" → "법정 정밀 산식 + 리포트" 〔P0〕
현재: 5종 근사치, 2025 시급.
목표: **2026 법정 수치·정확 산식·근거 설명·리포트화**.

- **수치 갱신·중앙관리**: 최저임금(2026 10,320), 월 환산 209h, 지연이자 20%, 4대보험 요율 등을 `lib/legal.js` 한 곳에서 관리(매년 갱신 1곳).
- **정확도 향상**:
  - 퇴직금: 평균임금(3개월 임금총액÷일수) 정의·상여/연차수당 포함 안내, DC/DB 구분.
  - 주휴수당: 주 15h·개근 조건, 최저임금 위반 검증(주휴 포함 환산).
  - 통상임금 vs 평균임금 **구분 가이드**(해고예고=통상, 퇴직금=평균).
  - 연차수당: 입사일/회계연도 기준 일수 산정, 1년 미만 월차.
  - 연장·야간·휴일: 5인 미만 가산 예외, 중복가산(야간+연장), 휴일 8h 초과 100%.
  - 신규: 최저임금 위반 점검, 실업급여 모의(상·하한), 4대보험·실수령액.
- **결과 = 미니 리포트**: 산식·근거 조항·가정·면책 표기 + "요약서/문서/노무사" 연계 + PDF.
- 백엔드(선택): 검증·로깅용 `/api/calc`(주로 클라 계산 유지, 토큰 0).

## C. 정보 콘텐츠(가이드) — "단문" → "전문 아티클" 〔P1〕
현재: 12편, 중간 길이.
목표: **검색 1페이지를 노리는 깊이 + 신뢰 장치**.

- 글당: 명확한 개요·정의·요건·금액·절차(표/플로우)·기한·증거·예시·체크리스트·FAQ·관련글·근거 조항·**판례/사례 요약**·최종수정일·**노무사 실명 감수 표기**.
- 분량·구조 표준화(목차 자동, H2/H3 위계, 콜아웃, 표).
- 콘텐츠 확장: 주제당 1편 → 세부 글 다편(예: 임금체불=신고절차/대지급금/지연이자/사례) → 카테고리 인덱스가 목록 역할.
- 운영: 콘텐츠 CMS화(현 inline → 데이터 분리), 발행/수정 이력, 감수 워크플로.
- SEO: 글·카테고리 **정적 페이지 확장**, 내부링크, 구조화데이터(Article/FAQ/Breadcrumb 완비), OG(자동 생성됨).

## D. AI 상담 설계 — "단일 프롬프트" → "사건별 정교 플로우"(연결은 마지막) 〔P1〕
현재: 범용 시스템 프롬프트 + 데모 폴백.
목표: **사건유형별 질의·구조화 출력·근거·가드레일** 설계 완비(키 넣으면 즉시 고품질).

- 유형 분류 → 유형별 **필수 질의 세트**(누락 시 추가질문) → **구조화 출력 스키마**(상황요약/쟁점/확인필요/예상금액·근거/준비자료/행동/상담필요도/긴급도).
- 근거 인용(법 조항)·단정 금지·민감정보 마스킹·위험행동 가드레일.
- 비용 통제: 분류=저가모델, 요약=고품질, 토큰 상한·캐싱.
- 이력 저장(동의 시), 요약서 자동 생성, 계산기/문서 자동 연계.

## E. 노무사 디렉토리 — "샘플 4 + 일부 공공데이터" → "실데이터 + 검색/프로필/예약" 〔P1〕
현재: 샘플 4 + ingest 스크립트.
목표: **실데이터 파이프라인 + 제대로 된 검색/프로필/예약**.

- 데이터: 근로복지공단 공공데이터 정제 자동화(정규화·중복제거·지역 파싱 시도/구), 직접등록 우선 노출, 옵트아웃 관리.
- 검색: 지역(시·도/구) + 분야 + 상담방식 + 오늘가능 + 온라인 + 정렬(후기/거리) + 페이지네이션.
- 프로필: 충실화(소개·분야·상담료·가능시간·후기·인증·콘텐츠) + 정식 예약 슬롯.
- 예약/후기: 예약 상태관리, 동의 후 요약서 전달, 후기 작성·검증.
- 표현: "추천" 금지·"정보 제공/검색" 유지(공인노무사법).

## F. 상담요약서 — 〔P1〕
- 정식 양식·PDF·자동 마스킹·동의 플로우·노무사 전달 연계·버전/타임스탬프.

## G. 백엔드 아키텍처·데이터 — "JSON 파일" → "영속 DB + 검증 + 보안" 〔P0〕
현재: 파일 저장, 기본 라우트.
목표: **신뢰 가능한 서버**.

- **데이터 저장소**: leads/bookings/consults/reviews → **SQLite(better-sqlite3)** 또는 구조화 JSON+백업. 스키마·인덱스·마이그레이션.
- **검증/보안**: 입력 검증(스키마), **rate limit**, 보안 헤더(helmet), CORS, 스팸/봇 가드(허니팟), 요청 크기 제한, 에러 처리·로깅(요청ID).
- **개인정보**: 수집 최소화, 보관기간·삭제 API, 동의 기록, 마스킹.
- **설정/운영**: `.env`(키·모델·DB경로), 헬스체크, 구조화 로그, 백업.
- **API 표준화**: 일관 응답·에러 포맷, 버전(`/api/v1`).

## H. 관리자(Admin) — 신규 〔P1〕
- `/admin`(인증): 상담 리드·예약·노무사·후기·콘텐츠 관리, 통계(전환·유입), 옵트아웃 처리, 데이터 내보내기. 간단 비밀번호/토큰 인증.

## I. 계정·이력(경량) — 〔P2〕
- 회원가입 없는 **익명 토큰**(로컬) 기반 상담 이력 저장 + 동의 시 서버 보관. 매직링크(이메일)로 기기 간 이어보기(선택).

## J. 법무·컴플라이언스 — 〔P0〕
- **개인정보처리방침·이용약관** 실문서 페이지, 동의 체크 플로우(상담 저장·노무사 전달·AI 학습 별도 동의).
- AI 면책 고지·노무사 알선 아님 고지 일관 적용.
- 개인정보보호법/AI 기본법(2026.1 시행) 고지·안전조치 반영.

## K. 프론트엔드 품질 마감 — 〔P0~P1〕
- 디자인 토큰(design/01~09) **전면 적용 마감**: 잔여 ad-hoc px/색 → 토큰. 컴포넌트 클래스 정착.
- **상태 전수**: 로딩(스켈레톤)·빈·에러·오프라인·503 전 화면.
- **접근성 감사**: axe/Lighthouse·키보드·스크린리더 1회 통과(WCAG 2.2 AA).
- **성능**: LCP(히어로), 이미지 lazy·치수, 폰트 swap, JS 분할(추후 번들러 검토).
- 반응형 최종 점검(320px~), 인쇄 스타일(문서·요약서·리포트).

## L. SEO·성장 인프라 — 〔P1〕
- 정적 글·카테고리 인덱스 정적화 확장, sitemap 자동화, robots, canonical, OG(자동), 구조화데이터 완비.
- analytics(개인정보 고려: Plausible 등), 검색 콘솔 제출, 성능 예산.

## M. 데이터 정확성 운영 — 〔P0〕
- 법령/수치(최저임금·요율) **연 1회 갱신 체크리스트** + 단일 소스(`lib/legal.js`).
- 콘텐츠·계산·문서의 "최종 검토일" 표기·감수 기록.

## N. 테스트·배포 — 〔P1〕
- 핵심 로직(계산기·문서 치환·API 핸들러) 단위 테스트.
- 배포: 도메인·호스팅(무료 티어), HTTPS, 환경변수, sitemap 제출, 모니터링/업타임.

---

## 실행 로드맵(제안 순서)
1. **P0 신뢰 코어**: B(계산기 정밀+2026수치) → A(문서센터 표준양식) → G(DB·보안·검증) → J(약관/개인정보) → M(수치 단일소스) → K(상태/접근성 마감).
2. **P1 차별화**: D(AI 설계) → C(콘텐츠 심화) → E(노무사 실데이터·검색·예약) → F(요약서 정식) → H(관리자) → L(SEO).
3. **P2 고도화**: I(이력/계정) → N(테스트/배포 자동화) → 다국어·다크모드.

## 제외(사용자/후속)
- 폰트(Pretendard woff2)·노무사 사진·히어로 영상·정교 PNG OG = 사용자 준비(슬롯 완비됨).
- 실제 AI API 키 연결 = 최종 단계(코드 준비 완료).

> 이 문서가 제품화 작업의 기준. 각 항목은 "현재 → 목표 → 구현"으로 합의 후 착수.
