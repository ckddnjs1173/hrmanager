## 8. 사이트 전역 버그 발견: 공용 계산기/문서센터/공식기관 등 7개 화면에 가짜 "내 사건" 탭 레일이 붙던 문제 → 제거

- **발견 경위**: 퇴직금 계산기(`#calc`→퇴직금) 스크린샷을 찍다가 화면 왼쪽에 "내 사건" 타이틀 + 개요/사실/금액/증거/행동/문서/근거 7탭 세로 내비게이션이 붙어있는 것을 확인. 코드 추적 결과 `product-ui.js`의 `addCaseRails()`가 `result/summary/calc/report/official/docs/solve` 라는 **화면 id만 보고** 이 7개를 "하나의 Case 진행 단계"로 오인해 전부에 같은 레일을 삽입하고 있었음.
- **실제로는** 이 7개는 서로 무관한 **독립된 공개 도구 화면**(계산기, 문서센터, 공식 기관, 노동청 진정 절차 등 — `tools.html`이 각각을 별도 링크로 안내)이라, 이 레일은 "계산기에서 문서센터로 넘어가는 탭"처럼 보이지만 실제로 그런 흐름이 존재하지 않는 오작동 UI였음. 레거시 renderHub 기반 단일-대화 케이스 흐름의 잔재로 추정(이전 세션에 발견된 "고아 renderHub 허브 화면"과 같은 계열).
- **체크리스트 관점에서도 위반**: 이 레일 자체가 화면마다 무관하게 반복되는 고정 사이드바 장식이라 "이 화면만 따로 봤을 때 구분이 안 되는가"(5번)에 해당 + 문서센터 리뷰를 시작하기 전에 반드시 제거해야 그 화면이 정직하게 검수됨.
- **수정**: `product-ui.js`에서 `addCaseRails()`/`railItems`와 그 전용으로만 쓰이던 아이콘 맵 제거, `init()` 호출부 정리. `product-ui.css`에서 `.ui-case-rail`/`.ui-case-screen` 관련 규칙(데스크톱+모바일) 제거. `test/product-ui-system.test.js`의 관련 3개 assertion을 "레일이 존재하면 안 된다"는 회귀 방지 테스트로 교체.
- **영향 범위**: `#calc`(계산기), `#docs`(문서센터), `#official`(공식 기관), `#report`(노동청 진정), `#result`/`#summary`/`#solve`(AI 상담 결과·요약·근거) 7개 화면 전부 — 문서센터·계산기 상세는 오늘 리뷰 대상이라 이 수정 없이는 정확한 검수가 불가능했음.

## 9. 계산기 개별 상세 3종 — Stripe식 정보 계층

같은 `#calc` 화면 안에서 종류만 바뀌는 구조(좌측 분야 아코디언 → 상단 법정 기준 배너 → 폼 → 결과)라 공용 골격은 1회만 검수하고, 아래 3종은 내용·수치 정확성 위주로 스팟체크.

- **퇴직금(임금체불/퇴직금 계열, `severance`)**: 근속일수·소정근로시간·3개월 총임금 입력 → 예상 퇴직금 큰 수치 + 재직일수 상세. `.claude/design-refs/2026-09-07/11-calc-severance.png`
- **통상임금(임금체불 계열, `ordinary`)**: 기본급·고정수당·정기상여 입력 → 통상시급 + 산식 공개 + 2024년 대법원 전원합의체 판례 각주. **1차 스크린샷에서 큰 수치(10,368원)와 하단 상세표(11,483원)가 달라 보여 계산 로직 버그로 의심했으나, 재확인 결과 카운트업 애니메이션이 끝나기 전에 캡처한 스크린샷 타이밍 문제였음**(스크립트 대기시간 400ms→1500ms로 늘려 재캡처 후 두 값 일치 확인, 계산 로직 코드는 수정하지 않음 — 오늘 스코프인 "순수 시각 디자인"을 지킴). `.claude/design-refs/2026-09-07/12-calc-ordinary.png`
- **노동법 자율점검(사업주 진단 계열, `audit`)**: 9개 항목 예/아니오 셀프 감사 드롭다운 — 카드/아이콘 없이 순수 폼. `.claude/design-refs/2026-09-07/13-calc-audit.png`
- **체크리스트**: 3종 모두 5/5 아니오 → **통과**. 필 버튼 없음(세그먼트 버튼 8~9px 라운드), 블러/그라데이션 없음, 아이콘 반복 없음(정보 배너의 단일 아이콘만), 헤드라인+리드+버튼+카드그리드 골격이 아니라 아코디언+폼+결과의 조밀한 유틸리티 골격, 산식·판례 각주 등 도메인 특화 내용으로 템플릿과 구분됨.
- **시도 횟수**: 공용 골격 1회(레일 버그 수정 포함 2회 소요) + 3종 각 1회(통상임금은 스크린샷 재캡처 1회 추가, 코드 수정 없음)

## 11. 가이드 상세 페이지 — 근로자(`임금체불`)/사업주(`고용장려금`) — 에디토리얼

- **화면 A — SaaS 비활성 상태**(`/advisor.html`, 평소 sqlite 서버): "협업 포털을 사용할 수 없습니다" 정직한 안내 카드. employer.html의 "Business Workspace 비활성화" 패턴과 동일한 정직성 원칙 확인.

- **1차 시도 문제**: `advisor.html`이 사이트의 다른 4개 토큰 세트(app.css/case-ui.css/saas-ui.css/product-ui.css)와도 다른 **별도의 5번째 독립 CSS 파일**(`advisor.css`)을 쓰고 있었고, 여기 `.chip`(ACTIVE/OPEN 상태 배지)과 `.advisor-doc-state`(문서 검토 상태 배지)가 `border-radius:999px` — 오늘 다른 곳들(business-ui-copy.css의 `.pill`, case-ui.css의 `.status-pill`, 문서센터 칩)에서 이미 일관되게 정리한 "상태 배지는 필 금지" 원칙에서 이 파일만 누락돼 있었음. `.advisor-card`(로딩/비활성 상태 카드)에도 `box-shadow:0 12px 30px rgba(...)` — Linear 참고의 "그림자 금지" 위반.
